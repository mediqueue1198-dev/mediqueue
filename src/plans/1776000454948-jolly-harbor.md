# MediQueue Google Authentication Implementation Plan

## Overview
Implement Google OAuth sign-in to allow users to authenticate using their Google accounts, with proper role assignment and routing to patient/doctor/mediator dashboards.

## Current State Analysis

### Project Structure
- **Frontend**: React 19 with Vite, TypeScript
- **Backend**: Supabase (PostgreSQL + Auth)
- **State Management**: Zustand
- **Routing**: React Router with ProtectedRoute component

### Authentication System
- Uses Supabase Auth with email/password
- `useAuth` hook provides `signInWithGoogle` stub (currently throws error)
- User roles stored in `users` table (patient, doctor, mediator)
- Registration form collects role information
- Role-based routing via `ProtectedRoute` and `RootRedirect`

### Database Schema
- `users` table: stores user email, full_name, phone, role, avatar_url
- `patients` and `doctors` tables: store role-specific information
- Row Level Security (RLS) enforced

```jsx
import { useEffect, useState } from 'react'
import { useNavigate } from 'react-router-dom'
import { useAuth } from '@/hooks/useAuth'
import { getRoleRedirect } from '@/utils/helpers'
import { PageLoader } from '@/components/ui/LoadingSpinner'

export default function GoogleCallback() {
  const { isAuthenticated, profile, error, login } = useAuth()
  const navigate = useNavigate()
  const [loading, setLoading] = useState(true)
  
  useEffect(() => {
    async function handleCallback() {
      try {
        // Exchange code for session
        const { data, error } = await supabase.auth.exchangeOAuthCodeForSession()
        if (error) throw error
        
        // Get session and profile
        const session = await supabase.auth.getSession()
        const userProfile = await loadUserProfile(session.user.id)
        
        // Determine role and redirect
        const role = userProfile?.role || 'patient'
        navigate(getRoleRedirect(role))
      } catch (err) {
        console.error('Google callback error:', err)
        navigate('/login')
      } finally {
        setLoading(false)
      }
    }
    
    handleCallback()
  }, [])
  
  if (loading) return <PageLoader label="Authenticating..." />
  return null
}
```

## How User Role is Determined

1. **During Registration**: User selects role (patient/doctor/mediator)
2. **After Google OAuth**:
   - If user exists in `users` table, use stored role
   - If new user, default to 'patient' or prompt for role selection
3. **Role-based Routing**: 
   - `RootRedirect` component checks `role` from profile
   - Redirects to `/patient`, `/doctor`, or `/mediator`
   - ProtectedRoute ensures only users with matching roles access specific pages

## Security Considerations
- Never commit Google Client Secret to version control
- Use environment variables for credentials
- Validate role assignments server-side
- Implement proper error handling for OAuth failures
